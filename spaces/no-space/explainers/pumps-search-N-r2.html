Pump failure prediction

A water utility runs about 400 pumps in 12 pumping stations. Each pump has vibration, temperature and pressure sensors that report every second. When a pump fails without warning, part of the town loses its water supply, so the utility wants to replace bearings and seals before they fail. Several stations are in rural areas with an unreliable mobile connection. The utility has two data scientists and relies on its IT department for servers and networks.

A1 · Hybrid edge scoring with shared learning

Stations issue warnings locally while a shared on-premises model improves from local inspection feedback. Family adapters isolate deployment, but model freshness and new-family lead time need validation.

Composed of 2 partial design points, one per ADR:

As a whole: The system runs pump-family-adapted inference at each station while training a shared fleet model centrally on utility-owned on-premises data. Stations incorporate local incremental updates and issue warnings during outages, buffering results and synchronizing them within 48 hours.

ADR1 · Where should scoring and outage handling run? Q1C1

Context. The utility requires warnings to reach station staff during up to two days without a connection, and sensor data must remain within utility premises. Central-only scoring keeps processing centralized but cannot deliver a warning over a failed link. Both hybrid and autonomous station scoring meet the data boundary while allowing local alerts.

Decision. Hybrid station inference (A1); Autonomous station inference (B1).

Hybrid station inference chosen in A1

Inference placement → Station-edge inference with central on-prem trainingOutage behavior → Local warnings with 48-hour buffered synchronizationData boundary → Utility-owned on-premises processing and storage

  • Local inference and warning buffering cover station connectivity loss.
  • Central training and storage stay on utility premises.
  • Edge deployment and delayed synchronization require operational support.

A1 combines local outage behavior with centrally managed on-premises model training.

Autonomous station inference chosen in B1

Inference placement → Station-local autonomous inference and learningOutage behavior → Local warnings with 48-hour buffered synchronizationData boundary → Utility-owned on-premises processing and storage

  • Stations can score pumps without a central connection.
  • Data and station updates remain on utility premises.
  • Local model operations and synchronization can diverge across stations.

B1 prioritizes station autonomy while preserving the data boundary.

Central-only inference discarded

Inference placement → Central on-prem inferenceOutage behavior → Queue warnings until central connection returnsData boundary → Utility-owned on-premises processing and storage

  • Central scoring and operations are straightforward to manage.
  • All processing stays on utility premises.
  • Warnings cannot reach the station during the outage.

It misses the explicit outage delivery requirement.

ADR2 · How should models use inspection findings and accommodate new pump families? R1R2Q2

Context. Predictions need useful lead time and probable causes, technician findings must improve them, and a new pump model must receive predictions within one month without changing existing scoring. Shared models can reuse fleet learning, while family-specific extensions can isolate new equipment. Local learning is responsive but needs validation; batch learning is controlled but may delay updates. Predictive accuracy and onboarding time require operational evidence.

Decision. Shared model with adapters and local feedback (A1); Shared calibrated model with station learning (B1).

Shared model with adapters and local feedback chosen in A1

Model strategy → Shared fleet model with pump-family adaptersFeedback path → Local incremental updates with later synchronization

  • Inspection findings can be used locally without waiting for central connectivity.
  • Adapters separate pump-family deployment from the shared model.
  • Local updates can diverge before synchronization, and prediction lead time is unproven.

A1 balances immediate feedback with reusable fleet learning and family-level isolation.

Shared calibrated model with station learning chosen in B1

Model strategy → Shared fleet model with family calibrationFeedback path → Local incremental updates with later synchronization

  • Family calibration offers an isolated route for a new model.
  • Technician findings can be applied locally.
  • Local updates need validation and may diverge; the one-month target is unverified.

B1 favors family-level modifiability and local responsiveness.

Shared adapters with central batch learning discarded

Model strategy → Shared fleet model with pump-family adaptersFeedback path → Central batch retraining from inspection labels

  • Inspection labels have a controlled path into shared model retraining.
  • Family adapters isolate deployment.
  • Batch feedback may delay prediction improvements and new-family onboarding.

The seed established a useful baseline, but its delayed feedback led to the local-update refinement.

Generic anomaly model discarded

Model strategy → Generic unsupervised anomaly detectorFeedback path → Technician-confirmed local calibration synced centrally

  • A generic detector can start scoring equipment with little model-specific preparation.
  • It does not establish probable cause or 24-hour lead time.

The generic anomaly score does not meet the central prediction need in R1.

  • Outage behavior → Local warnings with 48-hour buffered synchronization
  • Data boundary → Utility-owned on-premises processing and storage

Observed Local inference supports outage warnings, and inspection labels have a defined route into training. The architecture alone does not establish the prediction lead time or demonstrate onboarding within one month.

R1 partlyR2 meetsQ1 meetsQ2 partlyC1 meets

The utility stores and processes data on premises, trains a shared fleet model centrally, and deploys pump-family adapters for station-edge inference. Stations issue local warnings during outages and buffer results for up to 48 hours, after which synchronized data and inspection labels support batch retraining.

The point's trade-off This preserves utility data control and warning availability while reusing a common model across pump families. It gives up rapid feedback and potentially fresh model updates, because labels arrive through inspections and synchronization may be delayed; maintaining adapters also adds coordination overhead.
