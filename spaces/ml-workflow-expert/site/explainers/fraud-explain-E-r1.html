Card-fraud scoring service

A payments company scores card transactions before authorization, at up to 15,000 transactions per second during seasonal peaks. Fraud labels arrive days to weeks later, and auditors may ask months later how a score was produced. Five data scientists and two ML engineers build and run the service without a dedicated ML platform team.

The solution

S · Fraud scoring service as built

A streaming feature pipeline feeds a synchronous model microservice with fallback authorization behavior. Nightly batch retraining is tracked and risk-reviewed before a new single production model is loaded.

ADR1 · Serve current card activity synchronously R1Q1Q2

Context. The switch needs a timely score using recent card activity. If scoring fails, authorization must continue through the rule engine.

Decision. Streamed features and model microservice.

“Flink jobs consume the topic and keep per-card aggregates (spend and counts over the last hour, day and week, and the number of distinct merchants) up to date in a Redis cluster.”

  • The synchronous service returns scores for the authorization decision.
